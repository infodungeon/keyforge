# ADR-018: Typestate Pattern for Job Lifecycle

* **Status:** Accepted
* **Date:** 2026-01-22
* **Context:** Jobs were managed using raw strings for status and `Option` fields for data that only exists in certain states. This "Humble Bag of Data" pattern allowed for invalid states (e.g., accessing a "final_score" on a "Pending" job).
* **Decision:** Implement the Typestate Pattern using distinct types: `Pending`, `Running`, and `Completed`.
* **Consequences:**
  * (+) Invalid states are unrepresentable at compile-time.
  * (+) API consumers (Hive, Agent) have clear, type-safe data contracts for each phase.
  * (+) Aligns implementation with `05_DESIGN_PATTERNS.md` and `07_FAILURE_MODES.md`.
  * (-) Slight increase in type complexity for persistence mappers.
