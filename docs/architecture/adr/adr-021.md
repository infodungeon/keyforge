# ADR-021: Type System Stabilization (100x Architecture)

* **Status:** Accepted
* **Date:** 2026-01-27

## Context

KeyForge requires a type system that enforces "Correct-by-Construction" invariants while minimizing cognitive friction ("Metadata Noise").

## Decisions

### 1. Structural Layers

**KEEP:** We are keeping the separation between Entity (in `keyforge-model`) and DTO (in `keyforge-protocol`). This is good and stays.

### 2. Flatten Nested Metadata

**FLATTEN:** We are removing the redundant `*Meta` structs (like `KeyboardMeta`). Instead of `kbd.meta.name`, we want `kbd.name`. We are inlining those fields directly into the main structs.

### 3. Newtypes

**KEEP:** We are keeping types like `Score(i64)` and `KeyIndex(u16)` to stay strongly typed and prevent mixing up numbers.

### 4. Typestate Lifecycle

**KEEP:** We are keeping the `Job<Pending>` / `Job<Running>` pattern to enforce the job lifecycle at the type level.

### 5. Separate Concerns / Merged Entities

**SPLIT:** We are splitting "God Objects" like `AnalysisReport` into focused sub-structs (e.g., `ScoreSummary`, `MetricBreakdown`) to separate merged concerns.

### 6. Clean Wired Format

**ADOPT:** We are using the `Dto` suffix for anything in the protocol layer to keep the wire format separate from the domain logic.

## Summary of Changes

| Abstraction | Decision | Rationale |
| :--- | :--- | :--- |
| **Entity vs DTO** | ✅ KEEP | Safe validation boundary |
| **Newtypes** | ✅ KEEP | Prevents primitive mixing |
| **Typestate** | ✅ KEEP | Enforces runtime lifecycle |
| **Nested *Meta** | ❌ REMOVE | Eliminates indirection noise |
| **God Objects** | ❌ SPLIT | Enforces SRP and clean boundaries |
