# ADR-022: Rich Domain Entities and Clean Hexagonal Boundaries

## Status
Accepted

## Context
An audit of the codebase (Issue #56) identified "Domain Anemia" where core entities (`Layout`, `Keyboard`, `MetricSet`) were passive data containers. Critical business rules and biomechanical facts (e.g., scissor detection, roll directions) were implemented as "Magic Logic" within the `keyforge-physics` kernel. Furthermore, the use of `f32` for geometric math and scoring accumulation violated the **KeyForge Law** of bit-perfect determinism.

## Decision
1. **Rich Domain Entities**: Shift from "Reactive Logic" to "Structural Integrity." Domain models will own their invariants and derived biomechanical facts.
2. **Semantic Type Foundation**: Replace magic numbers/strings with exhaustive enums (`Hand`, `Finger`, `Zone`, `Direction`).
3. **Fixed-Point Geometry**: Transition from `f32` coordinates to `SpatialUnit(i32)` (1000 units = 1.0 KU) to ensure bit-perfect spatial determinism.
4. **Biomechanical Fact Migration**: Move the *definition* of biomechanical events (Scissors, Stretches, Rolls) from the Use Case layer (`physics`) to the Entity layer (`model`).
5. **Hexagonal Formalization**: 
    - Implement explicit **Inbound Ports** (`LayoutOptimizer`) in `keyforge-protocol` to decouple adapters from evolution logic.
    - Implement explicit **Outbound Ports** (`ScoringEngine`) to decouple use cases from specific hardware-optimized engines.
6. **Model-DTO Boundary**: Remove serialization logic (`serde`) from domain entities. Entities remain pure; `Protocol` DTOs handle I/O and validation gates (`TryFrom`).

## Consequences
- **Pros**:
    - **Correct-by-Construction**: Invalid states become unrepresentable in the type system.
    - **Bit-Perfect Determinism**: Guarantees identical scoring results across all CPU architectures.
    - **Logic Parity**: Unified definitions for UI visualization and Engine evaluation.
    - **Modularity**: Enables hot-swapping optimization engines without touching application code.
- **Cons**:
    - **Critical Complexity**: Requires a near-total rewrite of the physics kernels and geometric logic.
    - **Breaking Changes**: Will invalidate current baseline snapshots and serialization formats.
