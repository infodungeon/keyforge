# ADR-025: Bit-Perfect Physics Analysis Accumulation

## Status
Proposed

## Context
The `analyze_layout` function in `libs/keyforge-physics` is the "Ground Truth" for layout evaluation. While optimized engines (AVX-512, NEON) use hardware-specific acceleration, they must remain bit-identical to the scalar kernel. Current implementation uses `f32` and `f64` for intermediate scaling and normalization (e.g., per 100k keypresses), which introduces non-deterministic rounding errors across different CPU architectures. This violates **ARCH-003** and prevents absolute oracle parity.

## Decision
1. **Total Float Purge**: Prohibit `f32`/`f64` in the `libs/keyforge-physics` logic kernels and analysis layer.
2. **High-Precision Integer Scaling**: Use `i128` for all intermediate products involving `Score` and frequency multipliers.
3. **Rounding-Safe Normalization**: Implement a `deterministic_normalize` helper that uses integer division with symmetric half-up rounding: `(product + (product.signum() * (divisor / 2))) / divisor`.
4. **Scale Invariants**: Maintain a consistent `1,000,000` scaling factor for all effort-based metrics.

## Consequences
- **Pros**:
    - **Absolute Parity**: Guarantees bit-identical results between scalar, SIMD, and WASM engines.
    - **Platform Independence**: Identical results on x86_64, ARM64, and Web platforms.
    - **Safe Accumulation**: `i128` provides enough headroom to prevent overflow even for extremely large corpora.
- **Cons**:
    - **Minor Overhead**: `i128` math is slightly slower than `f64` on some architectures (negligible for analysis).
