# ADR-027: Path Traversal Prevention via SafePath Newtype

* **Status:** Proposed
* **Date:** 2026-02-09
* **Context:** 
  The `narsil` security scanner identified 102 Path Traversal (CWE-22) vulnerabilities across the `keyforge` codebase. While a `normalize_path` helper exists in `keyforge-infra`, its application is inconsistent. Direct use of `std::fs` and `tokio::fs` with unvalidated `String` or `Path` inputs persists in the repository and CLI layers.

* **Decision:**
  1. **SafePath Newtype:** Create a `SafePath` newtype in `keyforge-model::types` that wraps `PathBuf`.
  2. **Infallible Validation:** The only way to construct a `SafePath` is through a fallible constructor (`try_new`, `from_str`) that executes strict normalization and traversal checks (e.g., prohibiting `..` and ensuring paths remain within the intended root).
  3. **Boundary Enforcement:**
     - Update all traits in `keyforge-adapter` and `keyforge-persistence` to accept `SafePath` instead of `Path` or `String`.
     - Implement `serde::Deserialize` for `SafePath` to ensure all external inputs (e.g., config files, API payloads) are validated at the moment of ingestion (aligning with ADR-006).
  4. **Quality Gate:** Implement an `ast-grep` rule to flag direct use of `fs` operations with raw `String`/`Path` types in production crates.

* **Consequences:**
  * (+) **Type-Level Security:** Path traversal becomes a compile-time or ingestion-time error, not a runtime vulnerability.
  * (+) **Centralized Logic:** Validation logic is no longer scattered across the codebase.
  * (-) **Refactoring Overhead:** Significant changes required in `keyforge-persistence`, `keyforge-infra`, and `keyforge-cli`.
  * (-) **Runtime Cost:** Slight overhead for path normalization during object creation.
