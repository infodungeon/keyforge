Data flows Up. code Ascii [keyforge-ui] --(depends on)--> [keyforge-workspace] | | | v +--------(depends on)--------> [keyforge-core] | v [keyforge-protocol] (Leaf Node) Visibility Rules: keyforge-protocol: Scope: pub everywhere. This is the shared language (DTOs). Constraints: Must NEVER import core or workspace. Pure logicless data. keyforge-core: Scope: ContextLoader, Scorer (methods), Optimizer: pub (Public API). PosMap, CostTables, MutationDeck: pub(crate) (Internal Only). Constraints: No std::fs, no reqwest, no tokio. Pure calculation. keyforge-workspace (The Missing Link): Scope: Exposes high-level I/O operations (ensure_corpus). Constraints: Handles all "File Not Found" errors and network retries.

Next Steps (The Plan) To align with this architecture, the specific next steps (Phase 2) are: Create crates/keyforge-workspace: Move the file downloading, hashing, and path resolution logic here. Refactor Consumers: Make keyforge-node, keyforge-cli, and keyforge-ui use keyforge-workspace to find their data. Strict Visibility: Fix the evolution vs scoring visibility issue properly so Scorer fields can be pub(crate). This ensures that "Orchestration" is not just a file, but a pipeline managed by the Workspace (Data Availability) and Context (Data Logic).
